# Hero right column — why the screenshot path keeps failing

The fake GitHub Check screenshot (`hero-block-check.png`) fails Chris review not because the CSS shell is weak — the void, arcs, and card tilt are fine — but because **the focal object is still a dashboard**: a rectangular UI capture with chrome, rows, and verdict widgets that reads as “dev tool / CI panel / PPT slide,” not as beauty, motion, or ToC skills delivery. Polishing drop-shadow and geometry around a PNG cannot change what the eye parses first (a second product surface competing with copy), and a generated mock doubles the trust problem — visitors smell illustration, not evidence. Pool × Jigsaw × Consensys heroes work when **one designed moment** (geometry, a single object, or real media) carries emotion; pasting a gate UI into a card frame is still Semgrep/dashboard cosplay with warmer ink. The left column is locked; the right column must pivot to abstract composition, a skill-install object, or real screen recording — not another screenshot in a prettier box.
